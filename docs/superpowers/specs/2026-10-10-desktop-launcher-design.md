# Native desktop launcher

The owner requested a Desktop launcher explicitly patterned after Atrium's Swift desktop app, then added App Store to that same launcher. Follow that existing native control-window design: two service sections with status, Start, Stop, Open and Logs; Open starts its service if necessary before opening the browser. The control window itself starts neither server. This is a launcher for the local source checkouts, not a bundled Python distribution.

Use independent user launchd jobs, `io.appengine.desktop.engine` and `io.appengine.desktop.store`, bound to loopback ports8770 and8780. Keep plists under Application Support rather than LaunchAgents, so closing the launcher leaves requested services running but opening a login session does not auto-start them. Stop removes only the exact launcher-owned job; healthy services started elsewhere may be opened but cannot be stopped by this launcher. Unexpected listeners are reported, never killed. Startup checks the service's actual HTTP identity and has a bounded timeout.

Defaults: app-engine repo embedded by build; sibling app-store and personal-apps; existing ~/.config/app-engine/app-state and app-store/store-data. A Settings dialog lets the owner select checkout, apps and store-data folders and ports. Validate ports, distinct ports, directories and interpreters before launching. Configuration cannot change while managed jobs are loaded, preventing orphaned jobs and confusing stop targets. Environment is explicitly constructed for local mode; no inherited public-origin setting or secret is copied.

ServiceConfiguration validates a service definition and produces launchd property-list data. ServiceManager performs probe/start/stop asynchronously and returns a status/message. AppDelegate renders native Cocoa views and sends explicit actions. Native identity/schema/port/argument tests and isolated real service smoke tests precede installation. Build script creates and signs App Engine.app, installs on Desktop without deleting an existing unrelated bundle, and leaves source/build steps reproducible. No Atrium process, LaunchAgent or signing identity is changed.
